# NewLife.MQTT 架构设计

> 版本：v5.0 | 日期：2026-07-20
> 需求对应：[需求文档](需求文档.md) | 功能清单：[功能清单](功能清单.md)

本文档描述 NewLife.MQTT 的整体架构和 PROT/TRAN/CLNT/ENT/SEC 模块设计。SRV 服务端详见 [SRV-服务端架构](SRV-服务端架构.md)，CLUS 集群详见 [CLUS-集群架构](CLUS-集群架构.md)。

## 1. 整体架构

### 1.1 五层分层

NewLife.MQTT 采用五层分层架构，自底向上为：基础层、传输层、协议层、业务层、应用层。

```
┌─────────────────────────────────────────────────────────────┐
│                    应用层 Application                       │
│  NewLife.MqttServer · MqttClient · AliyunMqttClient        │
├─────────────────────────────────────────────────────────────┤
│                    业务层 Business                          │
│  MqttServer · MqttExchange · MqttBridge · MqttRuleEngine   │
│  MqttWebHook · ClusterServer · IMqttAuthenticator          │
├─────────────────────────────────────────────────────────────┤
│                    协议层 Protocol                          │
│  MqttHandler · MqttFactory · 15种消息 · MqttCodec          │
│  MqttProperties(30种属性) · MqttTopicFilter                │
├─────────────────────────────────────────────────────────────┤
│                    传输层 Transport                         │
│  TCP · TLS · WebSocket · WSS · QUIC · 可靠UDP · Proxy     │
├─────────────────────────────────────────────────────────────┤
│                    基础层 Foundation                        │
│       NewLife.Core (网络/序列化/日志/缓存/追踪)            │
└─────────────────────────────────────────────────────────────┘
```

## 2. 数据模型（PROT 协议编解码）

### 2.1 消息继承体系

```
MqttMessage                     -- 基类：Type/QoS/Retain/Duplicate/Properties(5.0)
  ├── ConnectMessage             -- CONNECT(1)
  ├── ConnAck                    -- CONNACK(2)
  ├── MqttIdMessage              -- 带报文标识符中间基类（Id: UInt16）
  │   ├── PublishMessage         -- PUBLISH(3)
  │   ├── PubAck                 -- PUBACK(4)
  │   ├── PubRec                 -- PUBREC(5)
  │   ├── PubRel                 -- PUBREL(6)
  │   ├── PubComp                -- PUBCOMP(7)
  │   ├── SubscribeMessage       -- SUBSCRIBE(8)
  │   ├── SubAck                 -- SUBACK(9)
  │   ├── UnsubscribeMessage     -- UNSUBSCRIBE(10)
  │   └── UnsubAck               -- UNSUBACK(11)
  ├── PingRequest                -- PINGREQ(12)
  ├── PingResponse               -- PINGRESP(13)
  ├── DisconnectMessage          -- DISCONNECT(14)
  └── AuthMessage                -- AUTH(15，MQTT 5.0)
```

### 2.2 固定头部结构

```
┌───────────┬──────────┬─────────────────────────────────────┐
│ Byte 1    │ Byte 2-5 │ Payload                             │
├───────────┼──────────┼─────────────────────────────────────┤
│ 4bit类型  │ 剩余长度 │ 可变头部 + 有效载荷                 │
│ 4bit标志  │ (变长)   │                                     │
└───────────┴──────────┴─────────────────────────────────────┘
```

变长编码（Remaining Length）：1~4 字节，每字节有效 7 位，最高位为延续标志。支持最大 268,435,455 字节（约 256MB）。由 `MqttMessage.ReadEncodedInt()` / `WriteEncodedInt()` 实现。

### 2.3 MQTT 5.0 属性系统

`MqttProperties` 管理 30 种属性，采用 `Dictionary<MqttPropertyId, Object>` 存储，支持 7 种数据类型。每种属性有唯一 ID（`MqttPropertyId` 枚举），在可变头部中以 TLV 格式编码。

**30 种属性按用途分组**：

| 分组 | 属性 | 说明 |
|------|------|------|
| 消息元数据 | PayloadFormatIndicator(0x01) / ContentType(0x03) / CorrelationData(0x09) / UserProperty(0x26) | 消息格式与自定义键值对 |
| 生命周期 | MessageExpiryInterval(0x02) / SessionExpiryInterval(0x11) / WillDelayInterval(0x18) | 消息和会话 TTL |
| 请求响应 | ResponseTopic(0x08) / RequestProblemInformation(0x17) / RequestResponseInformation(0x19) / ResponseInformation(0x1A) | MQTT 5.0 请求/响应模式 |
| 流控 | ReceiveMaximum(0x21) / TopicAliasMaximum(0x22) / TopicAlias(0x23) / MaximumPacketSize(0x27) | 会话能力协商 |
| 服务端能力 | MaximumQoS(0x24) / RetainAvailable(0x25) / WildcardSubscriptionAvailable(0x28) / SubscriptionIdentifierAvailable(0x29) / SharedSubscriptionAvailable(0x2A) | CONNACK 能力声明 |
| 认证 | AuthenticationMethod(0x15) / AuthenticationData(0x16) | 增强认证 |
| 标识 | AssignedClientIdentifier(0x12) / SubscriptionIdentifier(0x0B) / ServerReference(0x1C) | 服务端分配标识 |
| 诊断 | ReasonString(0x1F) / ServerKeepAlive(0x13) | 错误原因与心跳覆盖 |

## 4. 技术选型

| 领域 | 选型 | 理由 |
|------|------|------|
| 基础框架 | NewLife.Core | 自有基础库，零外部依赖 |
| 网络通信 | NewLife.Net（NetServer/NetClient） | 400 万 TCP 长连接已验证；网络层裸包 1.4 亿/秒 |
| RPC 通信 | NewLife.Core 内置 HTTP RPC（HttpServer 控制器 + ApiHttpClient） | 集群节点间通信，零额外依赖 |
| 消息编解码 | NewLife.Core v12 消息泵（IMessageCodec + MessagePump） | 帧定界与请求-响应配对统一交给帧层 |
| 并发容器 | ConcurrentDictionary / ConcurrentQueue | 线程安全无锁读 |
| 原子操作 | Interlocked | 报文标识符分配、统计计数 |
| 异步锁 | SemaphoreSlim | 客户端连接保护 |
| 定时器 | TimerX | 高精度，避免 ThreadPool 竞争 |
| 序列化 | NewLife.Core 内置 JSON/Binary | 不引入第三方 JSON 库 |
| 日志追踪 | ILog + ITracer | NewLife.Core 统一日志和 APM |
| QUIC 传输 | System.Net.Quic（.NET 7+） | ALPN "mqtt" |
| 主题匹配 | Trie / PruningRadixTrie | 高效前缀树，加速通配符匹配 |
| 开源协议 | MIT | 最宽松协议 |

## 5. 关键设计决策

| 决策 | 方案 | 否决方案 | 选择理由 |
|------|------|---------|---------|
| 交付形态 | 单一 NuGet 包包含客户端+服务端 | 客户端/服务端分包（增加用户选择负担、版本碎片化） | 极简集成，用户无需判断装哪个包 |
| 依赖策略 | 仅依赖 NewLife.Core | 引入第三方 JSON/网络库（增加供应链安全风险、版本兼容困难） | 消除供应链安全风险，net45~net10 全兼容 |
| 多协议支持 | 分端口接入（TCP/TLS 走 MQTT 端口，WebSocket 走独立 HttpServer 桥接） | 单端口多协议嗅探（升级路径与 MQTT 帧混杂，HTTP 与 WS 解析互相牵制） | 各传输互不干扰，WebSocket 复用标准 HTTP 服务能力 |
| 扩展机制 | 接口 + ObjectContainer DI | 抽象基类（强制继承、灵活性差）；配置文件驱动（静态、不可测试） | .NET 标准模式；生命周期清晰 |
| 可靠 UDP | 自研（帧头+序列号+Ack+超时重发） | 基于 QUIC 降级（需要 msquic，低版本 ARM Linux 不可用）；TCP fallback（丢失 UDP 低延迟优势） | 全平台可用，无需 msquic |
| 集群通信 | 独立端口（2883）+ HTTP RPC | 复用 1883 端口（协议混杂风险，客户端连接影响集群稳定性） | 与客户端连接完全隔离 |
| 主题匹配 | PruningRadixTrie + MqttTopicFilter | 正则表达式匹配（性能差）；HashMap 精确匹配（不支持通配符） | 前缀树剪枝，大规模主题场景高效 |
| MQTT 3.1 兼容 | 接受 `MQIsdp` 连接，宽松 ClientId | 仅支持 3.1.1+（丢失存量设备） | 存量 IoT 设备兼容 |
| MQTT 5.0 属性裁剪 | V5.0→V3.x 桥接时自动裁剪 | 拒绝 V5.0→V3.x 桥接（限制互操作）；全量透传（V3.x 客户端无法解析） | 保留核心语义（Topic/Payload/QoS/Retain） |

## 6. 核心交互流程

### 6.1 客户端连接（CONNECT / CONNACK）

```
Client                                    Server
  │  1. TCP 握手                           │
  │──────────────────────────────────────>│
  │  2. CONNECT（ProtocolName+Level+       │
  │     ClientId+Username+Password+        │
  │     KeepAlive+CleanSession+Will)       │
  │──────────────────────────────────────>│
  │                       3. 版本识别:      │
  │                          MQIsdp→V310   │
  │                          MQTT 0x04→V311│
  │                          MQTT 0x05→V500│
  │                       4. 认证鉴权       │
  │                       5. 创建/恢复会话  │
  │  6. CONNACK（ReturnCode+SessionPresent │
  │     +5.0 能力声明）                    │
  │<──────────────────────────────────────│
  │  7. 若 SessionPresent=1:              │
  │     恢复订阅 + 推送离线消息            │
  │<──────────────────────────────────────│
```

### 6.2 QoS 消息交互

```
QoS 0: Client ──PUBLISH(QoS=0)──> Server      (至多一次)
QoS 1: Client ──PUBLISH(QoS=1,Id=N)──> Server
       Client <──PUBACK(Id=N)────────── Server (至少一次)
QoS 2: Client ──PUBLISH(QoS=2,Id=N)──> Server
       Client <──PUBREC(Id=N)────────── Server
       Client ──PUBREL(Id=N)──────────> Server
       Client <──PUBCOMP(Id=N)────────  Server (恰好一次)
```

### 6.3 消息路由与分发

`MqttExchange.Publish()` 流程：Retain 处理 → `$SYS` 独立分发 → 订阅者遍历匹配（含通配符+共享订阅+NoLocal 过滤）→ QoS 降级分发 → 主题别名分配 → 流控检查。

详细路由流程见 [SRV-服务端架构](SRV-服务端架构.md) §2。

## 7. 传输协议架构（TRAN）

### 7.1 支持矩阵

| 传输方式 | 客户端 | 服务端 | 端口 | 实现类 |
|---------|:---:|:---:|:---:|------|
| TCP | ✅ | ✅ | 1883 | NetClient/NetServer |
| TCP+TLS | ✅ | ✅ | 1883 | SslProtocol + X509（pfx/pem） |
| WebSocket | ✅ | ✅ | 独立 | `WebSocketClient`（客户端）/ `MqttWebSocketHandler`（服务端独立 `HttpServer` 桥接，`EnableWebSocket`/`WebSocketPort`，子协议 `mqtt`） |
| WSS | ✅ | ✅ | 独立 | WS + `WebSocketCertificate` |
| QUIC | ✅ | — | 14567 | `MqttQuicTransport` / `QuicClient`（.NET 7+） |
| 可靠 UDP | ✅ | ✅ | 1883 | `MqttUdpTransport`（自研可靠传输层） |
| ProxyProtocol | — | ✅ | — | `MqttCodec` 定界为 `MqttProxyFrame`（v1 文本 / v2 二进制） |
| MQTT-SN | ✅ | ✅ | 1884 | `MqttSnClient` / `MqttSnGateway`（UDP） |

### 7.2 编解码器链

服务端分端口承载，不再同端口自动识别协议类型：

```
TCP（1883）  ：网络数据 → MqttCodec（内建 PROXY 头定界）→ MqttMessage
WebSocket（8083）：网络数据 → HttpServer + MqttWebSocketHandler → WS 二进制消息定界为 MQTT 帧 → MqttSession
```

客户端例（WebSocket）：

```
网络数据 → WebSocketClient（v12 WebSocketCodec，二进制消息）→ MqttCodec 定界 → MqttMessage
```

WebSocket 客户端没有协议泵配对（WS 编解码器不实现 IMessageMatcher），请求-响应由 `MqttClient` 自管等待队列，按帧类型与标识符配对。

### 7.3 MQTT over 可靠 UDP（独创）

自研可靠传输层，4 字节帧头：帧类型（1 字节）+ 序列号（3 字节），通过 Ack 确认 + 超时重发保证可靠性，全平台可用，无需操作系统 msquic 支持。

### 7.4 MQTT-SN v1.2（TRAN-5）

UDP 传感器网络协议，通过网关透明桥接到标准 MQTT Broker：

```
MqttSnClient(UDP) ──► MqttSnGateway(UDP:1884) ──► MqttClient ──► MQTT Broker
                            │
                    主题ID注册表 + ADVERTISE广播 + 遗嘱代理
```

## 8. 模块设计概要

### 8.1 PROT 协议编解码

`Messaging/` 目录下 15 种消息类型 + 30 种 5.0 属性的完整编解码。核心类型：`MqttMessage`（基类）、`MqttFactory`（报文工厂）、`MqttCodec`（v12 消息泵上的帧编解码器，实现 `IMessageCodec` 与 `IMessageMatcher`）、`MqttFrame`（帧载体）、`MqttProperties`（属性容器）、`MqttTopicFilter`（主题过滤器）。

报文标识符（UInt16）通过 `Interlocked.Increment` 线程安全分配。各报文类型通过 `GetFlag()` 独立校验固定标志位。

### 8.2 CLNT 客户端

`MqttClient` 是全功能客户端入口，核心机制：

| 机制 | 实现 |
|------|------|
| 多协议传输 + SOCKS5 | URI Scheme 解析（`tcp://`/`ssl://`/`ws://`/`wss://`/`quic://`/UDP）+ SOCKS5 代理支持 |
| 遗嘱消息 | Will Topic/Message/QoS/Retain 设置，异常断开自动发布，正常 DISCONNECT 清除 |
| 生命周期事件 | `Connected` / `Disconnected` / `Received` 事件通知 |
| 自动重连 | 指数退避 `2^n`，`InitialReconnectDelay`/`MaxReconnectDelay`/`MaxReconnectAttempts` 可配 |
| 自动重订阅 | `_subs` 字典维护订阅关系，`ConnectAsync()` 中自动重发 |
| Inflight 管理 | `InflightManager` 超时重发（DUP=1，10s/3 次），`OnMessageAbandoned` 回调 |
| 心跳保活 | `TimerX` 半周期 Ping |
| 连接保护 | `SemaphoreSlim` 双重检查，连续 3 次 `TaskCanceledException` 自动销毁重建 |
| 阿里云适配 | `AliyunMqttClient` HMAC 签名 + 属性上报 + 时钟同步 |

### 8.3 ENT 企业扩展

| 功能 | 核心类型 | 说明 |
|------|---------|------|
| 消息桥接 | `MqttBridge` | In/Out/Both 三方向，复用 `MqttClient`，前缀映射，V5→V3 属性裁剪 |
| 规则引擎 | `MqttRuleEngine` | 主题匹配，5 种动作：Republish/WebHook/Bridge/Drop/Custom |
| WebHook | `MqttWebHook` | 6 种事件异步 HTTP POST，失败重试（默认 3 次） |
| 运行统计 | `MqttStats` | 1 秒滑动窗口，连接数/消息数/字节数/速率 |
| 阿里云 IoT | `AliyunMqttClient` + `MqttSign` | HMAC 签名自动化 |

### 8.4 SEC 安全增强

| 功能 | 核心类型 | 算法/模式 |
|------|---------|----------|
| 连接速率限制 | `MqttConnectionRateLimiter` | IP 滑动窗口 |
| 消息速率限制 | `MqttMessageRateLimiter` | 令牌桶（按客户端） |
| 三级黑白名单 | `MqttAccessList` | IP/ClientId/主题 + 装饰器模式 |
| JWT 认证 | `MqttJwtAuthenticator` | HS256 + Claims 主题授权 |

## 9. 性能设计

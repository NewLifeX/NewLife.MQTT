# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 31 种语言｜英文为源文与兜底

## 1. 语言分层

本库主库、存储组件与服务端示例均对齐 NewLife.Core 的 31 种语言。缺失译文在运行时自动回退英文，新增语言不需要改代码。

运行时语言由 `NewLife.Localization.Culture` 决定，默认跟随 `CultureInfo.CurrentUICulture`；日志可用 `NewLife.Localization.LogCulture` 固定为宿主语言，避免随请求变化。语言表由源生成器在模块初始化时注册，NativeAOT 下同样可用。

## 2. 词表文件

- `NewLife.MQTT/Locales`：主库词表，31 种语言
- `NewLife.MQTT.Storage/Locales`：存储组件词表，31 种语言
- `NewLife.MqttServer/Locales`：服务端示例词表，31 种语言（含配置项描述）

- 文件名即 BCP 47 语言代码；英文是源文与兜底，**不需要** `en.yml`。
- 键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。
- 运行时语言表是进程级全局表：多个程序集注册的同语言词条会合并，后注册者只补充缺失键。

## 3. 新增一条消息

1. 代码中写英文源文：`throw new XException(L.T("Session {0} is closed.", sessionId));`。异常消息不会经过日志器翻译，必须显式 `L.T`。
2. 无前缀日志直接调用 `Log.Info(format, args)`，内置日志器会自动翻译；**带实例前缀的日志必须使用 `Log.InfoPrefixed(prefix, format, args)`**，前缀在翻译之后拼接，避免整串查表失败。自定义日志级别使用 `Log.WritePrefixed(level, prefix, format, args)`。
3. **禁止把插值字符串传给日志**：`Log.Info($"...")` 与 `WriteLog($"...")` 生成的是动态整串，无法查表；一律改用 `Log.Info("... {0}", value)` 形式。
4. 运行时 HTML/JSON（如管理看板）中的固定文案同样使用 `L.T`，按当前 `Localization.Culture` 在请求时渲染；HTML 文本与 JS 字符串分别经过 `Html`/`Js` 转义。
5. 配置项使用英文 `[DisplayName("...")]` 与 `[LocalizedDescription("English source.")]`，XML 注释保持中文；读取显示名/描述时按当前语言翻译。
6. 程序集标题与描述使用英文源文，译文放入词表并由 `Locales/metadata-keys.json` 声明；`PackageDescription` 采用英中双语（NuGet 元数据不支持按语言切换）。
7. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
8. 运行校验脚本确认键集合、占位符与格式说明符一致。缺失译文按语言汇总为警告，不再阻断 CI；`-Strict` 可恢复键集合严格校验，`-SkipSource` 可跳过源码消息检查。

## 4. 校验

```powershell
pwsh -File tools/check-locales.ps1 \
  -LocaleDir NewLife.MQTT/Locales \
  -SourceDir NewLife.MQTT,NewLife.MQTT.Storage,NewLife.MqttServer
```

脚本检查四类问题：

- 键集合、占位符与格式说明符是否一致
- 基准词表中存在、源码中已找不到的孤儿键
- `L.T`、`WriteLog`、`Log.*` 与 `*Prefixed` 的源码消息是否有基准词条
- `WriteLog($"...")` 等动态插值日志（无法本地化）
- `metadata-keys.json` 中声明的程序集标题/描述等元数据键是否覆盖全部 31 种语言

CI 的 localization job 会对三个词表目录分别执行同一脚本。脚本统一放在 `tools/`，根目录不再保留 `.ps1`。

## 5. 覆盖现状

- 主库 31 种语言词表完整覆盖运行时日志、异常、关闭原因与管理看板文案，缺失条目运行期回退英文。
- `NewLife.MQTT.Storage` 与 `NewLife.MqttServer` 各自维护独立 31 语言词表，覆盖存储失败、示例服务端日志与配置项描述，由源生成器在所属程序集初始化时注册。
- 配置项通过英文 `DisplayName` + `LocalizedDescriptionAttribute` 在读取显示名/描述时按当前语言翻译，配置中心/管理界面无需额外适配。
- 程序集标题与描述由 `metadata-keys.json` 声明，31 种语言全部有译文；NuGet 包描述采用英中双语。
- 管理看板在每次请求时按 `Localization.Culture` 渲染，并同步设置 `<html lang>`；管理 API 的兜底错误消息同样本地化。

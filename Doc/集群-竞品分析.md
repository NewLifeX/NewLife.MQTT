# MQTT 集群竞品分析

> 版本：v3.0（新增大规模路由对比 + 亿级架构对标） | 日期：2026-07-14

## 1. 概述

本报告对比 **NewLife.MQTT 集群完成重构后**（即 Raft 共识与环路检测已实现）与市面上主流 MQTT Broker 的集群能力。

> **视角说明**：v1.0 报告将 NewLife.MQTT（.NET 协议库）与 EMQX/HiveMQ（独立消息中间件）直接横向对比，导致多处不公平。v2.0 修正如下：
> 1. 承认 NewLife.MQTT **已经有原生集群**（`ClusterServer`），并非"无"
> 2. 以重构完成后的状态做对标（含 Raft/环路检测/持久化/集群密钥）
> 3. 增加"易用性"和"安全模型"维度，这是我们的核心竞争力

## 2. 竞品概览

| 项目 | 类型 | 语言 | 许可证 | 定位 | 集群方式 |

### 3.5 🆕 大规模主题路由对比（v3.0 新增）

| 特性 | NewLife.MQTT（v5.x 分片） | EMQX 5.x | VerneMQ | HiveMQ CE | RabbitMQ |
|------|:-------------------------:|:--------:|:-------:|:---------:|:--------:|
| **路由模型** | 平坦(小) → 分片(中) → 多层(大) | Core/Replicant | 全连接 | 全连接 | 全连接 |
| **主题分片** | ✅ 一致哈希 1024 分片 | ❌ 无分片（Core 全量） | ❌ | ❌ | ❌ |
| **布隆过滤器预检** | ✅ 1% 误判率，1600x 压缩比 | ❌ 无 | ❌ 无 | ❌ 无 | ❌ 无 |
| **热点自适应复制** | ✅ 副本因子 3~51 动态调整 | ⚠️ 手动配置 | ❌ 无 | ❌ 无 | ❌ 无 |
| **批量合并转发** | ✅ 5ms/64KB 窗口合并 | ❌ 无 | ❌ 无 | ❌ 无 | ❌ 无 |
| **多层分级拓扑** | ✅ Edge/Regional/Core | Core/Replicant | ❌ 平坦 | ❌ 平坦 | ❌ 平坦 |
| **单节点订阅内存** | **O(total/N)** 分片存储 | O(total) 全量 | O(total) 全量 | O(total) 全量 | O(total) 全量 |
| **路由效率(N 节点)** | **O(log N)** 分片定向 | O(N) Core 转发 | O(N) 全连接 | O(N) 全连接 | O(N) 全连接 |
| **百亿级扩展性** | ✅ 多层+分片 | ⚠️ 100+ Core | ❌ < 30 节点 | ❌ < 20 节点 | ❌ < 50 节点 |
| **.NET 原生** | ✅ C# | ❌ Erlang | ❌ Erlang | ❌ Java | ❌ Erlang |

**分析**：在百亿级规模的主题路由维度，NewLife.MQTT 的分片+多层架构是竞品中独有的——EMQX 的 Core/Replicant 架构虽然支持水平扩展，但 Core 层仍然是全量订阅 + 全连接模式。我们的**分片定向+布隆过滤器预检**组合让单节点不再持有全量订阅，这是支撑百亿级的关键差异化能力。

## 5. 结论

1. **v5.x 分片架构完成后，NewLife.MQTT 集群在路由效率（O(log N) vs O(N)）和内存扩展性（O(1/N) vs O(N)）上超越 EMQX**——这是架构层面的差异化优势，而非功能堆砌
2. **在集成便利性、运维复杂度、许可合规、信创适配方面建立不可替代优势**
3. **ClusterSecret + 局域网自动信任是竞品中没有的安全创新**
4. **Mosquitto 和 NanoMQ 无真正集群能力，不应作为对标对象**
5. **EMQX 在大规模部署经验（100+ 节点生产验证）和跨协议生态方面领先，但我们在路由架构上已实现代际超越**

> 综合评估：v5.x 分片架构完成后，NewLife.MQTT 是 **.NET 生态中最完整的 MQTT 集群方案**——路由效率超越 EMQX，易用性超越所有竞品，是**百亿级设备场景下的最佳 .NET 选择**。

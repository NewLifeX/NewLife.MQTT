# NewLife.MQTT 需求文档

> 版本：v4.0 | 日期：2026-07-15

本文档描述 NewLife.MQTT 的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)或各模块架构文档中展开。

## 1. 背景与愿景

### 1.1 系统定位

NewLife.MQTT 是一款**纯国产、零第三方依赖、客户端与服务端一体**的 MQTT 全协议实现库。面向 IoT 设备开发者、平台运维工程师、业务系统集成商和信创项目负责人，提供从协议编解码到企业级 Broker 的一站式 .NET MQTT 解决方案。

| 产品/工程 | 定位 |
|-----------|------|
| `NewLife.MQTT`（NuGet 包） | 核心库：协议编解码 + 客户端 `MqttClient` + 服务端 `MqttServer` + 集群 + 桥接 + 规则引擎，一体化交付 |
| `NewLife.MqttServer` | 开箱即用的 MQTT Broker 应用，集成 Stardust 注册中心 |
| `NewLife.MQTT.Storage` | 持久化扩展：`IStorageProvider` → Redis / 数据库，消息和会话持久化 |

### 1.2 愿景

- **协议完整**：MQTT 3.1 / 3.1.1 / 5.0 全版本 + MQTT-SN v1.2 全覆盖，所有报文和属性零遗漏
- **零依赖**：仅依赖 NewLife.Core 基础库，NuGet 依赖链中无任何第三方包，消除供应链风险
- **客户端+服务端一体**：单一 `NewLife.MQTT` NuGet 包同时提供完整客户端和全功能 Broker
- **六种传输**：TCP / TLS / WebSocket / WSS / QUIC / 可靠 UDP 全覆盖，其中可靠 UDP 全球独创
- **企业功能免费**：集群 / 桥接 / 规则引擎 / WebHook / ACL / $SYS 全部内置免费，无企业版付费壁垒
- **信创合规**：纯国产自主研发 + MIT 开源 + 零第三方依赖 + 国产 OS/CPU 全支持

## 3. 功能需求

### 3.1 M1 协议编解码

- **M1-1 MQTT 3.1/3.1.1 报文编解码**：14 种报文类型（CONNECT ~ DISCONNECT）完整序列化与反序列化，包括 MQTT 3.1 协议名（`MQIsdp`）识别。
- **M1-2 MQTT 5.0 属性系统**：30 种属性标识符 + 7 种数据类型（Byte/UInt16/UInt32/变长整数/UTF-8字符串/二进制/字符串对）完整编解码。
- **M1-3 固定头部与粘包拆包**：4 位类型 + 4 位标志 + 1~4 字节变长剩余长度（最大 256MB），`MqttCodec` + `PacketCodec` 流式解析，各报文类型标志位独立校验。

### 3.2 M2 客户端

- **M2-1 多协议传输接入**：TCP（`tcp://`）/ TLS（X509 证书，pfx/pem）/ WebSocket（`ws://`）/ WSS（`wss://` 自动 TLS）/ QUIC（`quic://`，.NET 7+）/ 可靠 UDP，六种传输方式统一连接接口。
- **M2-2 发布/订阅/退订与消息回调**：QoS 0/1/2 完整确认流程（含 QoS 2 四步握手），订阅即绑定回调，按主题通配符（`+` / `#`）模糊匹配分发，重复订阅自动去重。
- **M2-3 遗嘱消息与生命周期事件**：Will Topic/Message/QoS/Retain 设置，异常断开时自动发布遗嘱，正常 DISCONNECT 时清除。`Connected` / `Disconnected` / `Received` 事件通知。
- **M2-4 断线重连与自动重订阅**：指数退避 `2^n` 重连策略（可配初始/最大延迟和最大尝试次数），重连后自动重发所有订阅（`_subs` 字典）。Inflight 消息队列超时重发（DUP=1，默认 10s/3 次）。KeepAlive 半周期心跳 Ping。
- **M2-5 便捷接入**：连接字符串一键初始化（`Init("Server=;UserName=;Password=;ClientId=;Timeout=")`），消息体编码器可替换（`IPacketEncoder`，默认 JSON），APM 性能追踪（`ITracer` Span 埋点），异步锁连接保护。

### 3.3 M3 服务端

- **M3-1 会话管理**：会话创建与注册（ConcurrentDictionary），30 秒定时扫描清理不活跃会话，持久会话（`PersistentSession`）保存订阅关系和离线消息队列（1000 条上限），CleanSession=0 恢复订阅+推送离线消息，CleanSession=1 清除旧会话，ClientId 映射查询。
- **M3-2 消息路由与分发**：精确匹配 + 通配符匹配（`+` 单层 / `#` 多层 / `$SYS` 屏蔽通配符），QoS 降级分发（取发布 QoS 和订阅 QoS 较小值），Retain 保留消息（存储 / 空 Payload 清除 / 新订阅推送），共享订阅轮询负载均衡（`$share/{group}/{topic}`），主题验证（最大长度 65536 字节 + 通配符位置合法性）。
- **M3-3 安全认证与 ACL**：可插拔 `IMqttAuthenticator` 认证接口，默认全放行（仅开发测试），`AuthorizePublish()` / `AuthorizeSubscribe()` 主题级权限控制（失败返回对应 ReasonCode）。
- **M3-4 $SYS 系统主题**：14 种标准系统主题定时发布（可配间隔默认 60 秒，`EnableSysTopic` 可关闭），包括在线连接数、消息/字节累计和速率、订阅数、主题数、保留消息数、运行时长、版本号。
- **M3-5 DI 可扩展架构**：`IMqttHandler`（Transient，每连接一实例）/ `IMqttExchange`（Singleton，全局消息交换机）/ `IMqttAuthenticator`（可替换），通过 `ObjectContainer` 注入，支持自定义处理器重写 `OnConnect`/`OnPublish`/`OnSubscribe` 等虚方法。
- **M3-6 MQTT 3.1 兼容接入**：识别 `ProtocolName="MQIsdp"` + `ProtocolLevel=0x03` 映射为 V310，CONNACK 兼容 3.1.1 格式，宽松 ClientId（不强制 23 字节），V310/V311/V500 三版本同服务端并存运行。
- **M3-7 持久化存储**：`NewLife.MQTT.Storage` 扩展项目，`IStorageProvider` 接口 → `DbExchange`（数据库持久化）+ `RedisExchange`（Redis 持久化），支持消息和会话的跨重启恢复。
- **M3-8 HTTP 管理 API 与 Dashboard**：RESTful JSON API（`MqttManagementServer`，查询连接/主题/统计/配置），内嵌 Web 看板（`MqttDashboard`，自动代理 API，默认端口 ManagementPort+1）。

### 3.4 M4 MQTT 5.0 增强

- **M4-1 增强认证与 SASL**：`AuthMessage` 挑战/响应流程（ReasonCode 0x00 成功 / 0x18 继续 / 0x19 重认证），`ISaslMechanism` 可插拔机制，`ScramSha256Mechanism` 标准实现，`MqttHandler.SaslCredentialStore` 凭据注入。
- **M4-2 主题别名双向管理**：客户端→服务端 `ResolveTopicAlias()` 绑定帧和引用帧解析，服务端→客户端 `AssignTopicAlias()` 自动分配别名以减少传输开销。
- **M4-3 流控与会话能力协商**：`ReceiveMaximum` → `CanSendQosMessage()` inflight 检查，`MaximumPacketSize` 发送前校验，`SessionExpiryInterval` 离线会话保活，`BuildConnAckProperties()` 服务端能力声明（MaximumQoS/RetainAvailable/Wildcard/SharedSubscription 等）。
- **M4-4 共享订阅**：`$share/{group}/{topic}` 格式解析 + `ExtractActualTopicFilter()`，同组多订阅者轮询负载均衡（`_sharedGroupIndex` 取模）。
- **M4-5 订阅选项与高级属性**：NoLocal 不转发给发布者 / RetainAsPublished 保留原始 Retain / RetainHandling 三种模式（0=订阅时发送 / 1=仅新订阅 / 2=不发送）。遗嘱延迟发布（`WillDelayInterval` 定时器）、消息过期清理（`MessageExpiryInterval` 分发时检查）、服务端 KeepAlive 覆盖（`ServerKeepAlive` 主动设置）、订阅标识符端到端透传（`SubscriptionIdentifier`）、请求/响应模式（`ResponseTopic` + `CorrelationData`）、服务端分配 ClientId（空 ClientId 时 `Rand.NextString(16)` 自动生成 + CONNACK `AssignedClientIdentifier` 回传）、服务端引用（`ServerReference` 迁移指示）、原因码扩展（CONNACK 20 种 + 所有 ACK ReasonCode + 服务端断开报文）。

### 3.5 M5 传输协议

- **M5-1 TCP / TLS / WebSocket / WSS**：标准 MQTT 传输，同端口 1883 自动识别协议类型（编解码器链：`ProxyCodec → WebSocketServerCodec → HttpCodec → MqttCodec`），TLS 1.2+ 支持 pfx/pem 证书，WebSocket 子协议标识 `mqtt`。
- **M5-2 MQTT over QUIC**：.NET 7+，基于 `System.Net.Quic`，ALPN `mqtt`，默认端口 14567。
- **M5-3 MQTT over 可靠 UDP**：自研可靠传输层（4 字节帧头 + 序列号 + Ack 确认 + 超时重发），全平台可用，无需操作系统 msquic 支持，覆盖 ARM Linux 4.x 等低版本内核。
- **M5-4 ProxyProtocol v1/v2**：服务端 `ProxyCodec` 解析 HAProxy/nginx 代理协议 v1（文本）和 v2（二进制），透传真实客户端 IP。

### 3.6 M6 集群

详见独立文档：[集群-需求文档](集群-需求文档.md) | [集群-架构设计](集群-架构设计.md) | [集群-功能清单](集群-功能清单.md)。

核心能力：节点管理（Join/Ping/Lease + 超时剔除）、跨节点订阅同步与消息转发（`ClusterExchange`）、自动节点发现（UDP 广播 / Consul / Stardust）、集群会话漂移（RPC 原子迁移）、Raft 共识引擎（订阅强一致 + 脑裂恢复）。

### 3.7 M7 企业扩展

- **M7-1 消息桥接**：`MqttBridge` 复用 `MqttClient` 实现 In/Out/Both 三种方向桥接，主题前缀映射（添加/去除前缀），QoS 上限控制，断线自动重连，V5.0→V3.x 自动裁剪属性。
- **M7-2 规则引擎**：`MqttRuleEngine` 基于 `MqttTopicFilter` 匹配消息主题，5 种动作：Republish（转发到新主题）/ WebHook（HTTP 推送）/ Bridge（桥接到远端）/ Drop（丢弃）/ Custom（自定义委托）。
- **M7-3 WebHook 事件推送**：`MqttWebHook` 在连接/断开/发布/投递/订阅/退订 6 种事件时异步 HTTP POST 推送，失败自动重试（默认 3 次），异步非阻塞不影响主流程。
- **M7-4 运行统计**：`MqttStats` 1 秒滑动窗口，连接数/消息数/字节数/订阅数/速率实时计算，配合 `$SYS` 系统主题发布。
- **M7-5 阿里云 IoT 适配**：`AliyunMqttClient` HMAC 签名自动化，属性上报，时钟同步，开箱即用对接阿里云 IoT 平台。

### 3.8 M8 安全增强

- **M8-1 连接速率限制**：`MqttConnectionRateLimiter` 基于 IP 滑动窗口限流，可配窗口大小和最大连接数，不同 IP 独立计数，超限拒绝新连接并记录日志。
- **M8-2 消息速率限制**：`MqttMessageRateLimiter` 基于令牌桶算法按客户端限速，可配每秒速率和突发大小，不同客户端独立令牌桶，令牌自动补充。
- **M8-3 三级黑白名单**：`MqttAccessList` 支持 IP / ClientId / 主题（发布+订阅）三级黑名单白名单，白名单优先于黑名单，装饰器模式可嵌套任意 `IMqttAuthenticator`。
- **M8-4 JWT 认证**：`MqttJwtAuthenticator` HS256 签名验证，exp/nbf/iss/aud 标准声明校验，pub/mqtt_sub 自定义声明主题级授权，Token 可放在 Password 或 Username 字段，零第三方依赖。

### 3.9 M9 MQTT-SN

- **M9-1 消息模型与编解码**：MQTT-SN v1.2 全部 23 种消息类型编解码（ADVERTISE ~ ENCAPSULATED），1/3 字节长度格式支持，变长头部字段正确解析。
- **M9-2 MQTT-SN 客户端**：UDP 通信，CONNECT/PUBLISH/SUBSCRIBE 消息收发，WILLTOPIC/WILLMSG 遗嘱设置，PINGREQ 心跳，REGISTER 主题注册，DISCONNECT 断开。
- **M9-3 MQTT-SN 网关**：UDP 端口监听（默认 1884），ADVERTISE 定期广播网关地址，客户端连接管理，主题 ID 注册表，MQTT-SN ↔ 标准 MQTT 双向透明桥接，遗嘱消息代理发布。

## 5. 不做什么

- **独立 Web 管理前端框架**：通过 HTTP API（M3-8）对接外部 UI，不内置 React/Vue 等前端框架。
- **内置数据库持久化**：持久化通过 `IMqttExchange` 接口扩展（核心库），或通过 `NewLife.MQTT.Storage` 扩展项目实现，核心库不捆绑特定数据库。
- **LDAP / OAuth 等外部认证协议**：提供 `IMqttAuthenticator` 接口供扩展，不内置实现。
- **.NET Framework 4.0 及以下版本**：最低支持 net45。
- **QUIC 服务端监听**：待 .NET 9+ QUIC 服务端 API 稳定后评估。
- **MQTT 6.0 协议**：标准未发布，不提前投入。

# MQTT 集成测试说明

> 版本：v1.1 | 日期：2026-10-16

## 概述

NewLife.MQTT 项目包含全面的集成测试，验证 MQTT 客户端和服务端的完整功能。测试覆盖 MQTT 3.1.1 和 MQTT 5.0 两个协议版本，确保服务端可同时支持两种协议的客户端连接和通信。另通过与第三方实现 MQTTnet 的双向交叉测试（见「交叉兼容测试」），证明协议互操作性。

## 测试文件

### 1. ComprehensiveMqttIntegrationTests.cs（综合集成测试）

**新增的综合测试文件**，系统化地覆盖所有核心功能，共 30 个测试用例。

#### 测试分类

##### 1. 连接功能测试（4 个测试）
- V311 客户端连接
- V500 客户端连接
- 多客户端同时连接
- 连接事件触发

##### 2. 订阅功能测试（4 个测试）
- V311 单主题订阅
- V500 单主题订阅
- 多主题订阅
- 通配符订阅（+ 和 # 通配符）

##### 3. 发布功能测试（6 个测试）
- V311 发布 QoS0/QoS1/QoS2 消息
- V500 发布 QoS0/QoS1/QoS2 消息
- 验证不同 QoS 级别的确认机制

##### 4. 消费（接收）功能测试（6 个测试）
- V311 发布 → V311 订阅接收
- V500 发布 → V500 订阅接收
- V311 发布 → V500 订阅接收（跨版本）
- V500 发布 → V311 订阅接收（跨版本）
- 一对多：一个发布者，多个订阅者
- 通配符订阅接收消息

##### 5. 断开功能测试（3 个测试）
- V311 正常断开
- V500 正常断开
- 断开后再次连接

##### 6. 高级功能测试（5 个测试）
- Retain 消息存储和传递
- 遗嘱消息：异常断开时发布
- 遗嘱消息：正常断开时不发布
- 心跳保活（Ping/Pong）
- 持久会话（CleanSession=false）

##### 7. 完整场景测试（2 个测试）
- 完整场景：连接→订阅→发布→接收→断开
- 完整场景：V311+V500 混合通信

### 3. MqttIntegrationTests.cs（基础集成测试）

原有的集成测试文件，覆盖 QoS 全路径、遗嘱消息、Retain 消息、会话持久化等功能，共 19 个测试用例。

### 4. QuicIntegrationTests.cs（QUIC 端到端，2026-10-16 新增）

验证 MQTT over QUIC 的完整链路：`quic://` 连接（CONNACK）、订阅、发布、接收，服务端使用自签名证书与临时 UDP 端口。

- 依赖操作系统 MsQuic：Windows 11+/Server 2022+ 自带，Linux 需安装 `libmsquic`（CI 已内置安装步骤）；
- 宿主不支持时用例显式跳过并在日志说明（不产生假阳性），CI 的 linux-x64 作业真实执行。

### 5. ShardRoutingE2ETests.cs（分片路由端到端，2026-10-16 新增）

验证 16 节点集群的分片路由正确性（CLUS-9 已知测试缺口收口）：

- 16 个 `ClusterServer` 真实组网，1024 个分片每片恰好 3 个互异副本且均属于集群；
- 主题→分片索引跨节点一致，路由目标数恒为副本数，分片分布不倾斜；
- 节点经 Ping 加入 / Leave 离开时，集群成员与分片路由环同步收敛。

### 6. 交叉兼容测试（CrossCompatibility，2026-10-16 补齐）

与第三方 MQTT 实现 [MQTTnet](https://github.com/dotnet/MQTTnet) 5.x（仅测试工程引用，不进入生产依赖）双向交叉验证，全部用例带 `[Trait("Category", "CrossCompatibility")]`：

| 模式 | 测试类 | 方向 | 覆盖 |
|------|--------|------|------|
| 我→你 | `XUnitTest.Integration.NewLifeClientCrossTests` | NewLife 客户端 → MQTTnet 服务端 | 连接/事件/Ping、QoS 0/1/2 全流程、Retain、遗嘱、`+`/`#` 通配符、断线重连、V500 发布订阅 |
| 你→我 | `XUnitTest.Integration.MqttnetClientCrossTests` | MQTTnet 客户端 → NewLife 服务端 | 连接/用户名密码、QoS 0/1/2、Retain、遗嘱、`+`/`#` 通配符、断线重连、V500 发布订阅、取消订阅、`$share` 共享订阅轮询分发 |
| 我→我 | `XUnitTest.Integration.NewLifeSelfE2ETests` | NewLife 客户端 ↔ NewLife 服务端 | QoS 1/2 端到端、多订阅者、手动重连、V500、取消订阅、持久会话离线补投 |

另见 `E2EScenarioTests` 场景9（NewLife 服务端 + MQTTnet 客户端双向 QoS1 互操作）。

服务端固件：MQTTnet 服务端由 `CrossIntegrationFixture` 提供（随机端口启动），NewLife 服务端由各测试类自身托管（`Port = 0` 自动分配）。

CI 覆盖：`.github/workflows/test.yml` 的 win-x64 / linux-x64 / linux-arm64 矩阵先执行本组用例（失败即阻断）再跑其余全量用例；linux-loongarch64 走 QEMU 仿真按类分批执行（批次含上述交叉测试类）。

## 测试特点

### 1. 端口自动分配
所有集成测试使用 `Port = 0`，让系统自动分配随机端口，避免端口冲突。

### 2. 协议版本覆盖
- **MQTT 3.1.1（V311）**：标准 MQTT 协议
- **MQTT 5.0（V500）**：最新 MQTT 协议，支持更多高级特性

### 3. 跨协议版本通信
验证服务端能够同时处理 V311 和 V500 客户端，且两种协议客户端之间可以正常通信。

### 4. 完整功能覆盖
- **连接管理**：连接、断开、重连
- **订阅管理**：单主题、多主题、通配符订阅
- **消息发布**：QoS0/1/2 三种服务质量等级
- **消息接收**：同协议、跨协议接收
- **高级特性**：Retain 消息、遗嘱消息、持久会话、心跳保活

### 5. 清晰的测试结构
每个测试用例都有：
- 清晰的中文 DisplayName，描述测试目的
- 明确的 Arrange-Act-Assert 结构
- 详细的断言消息，失败时易于定位问题

## 注意事项

### 1. 测试环境
- 测试框架：xUnit 2.9.3
- 目标框架：net10.0
- 构建配置：Release 模式

### 2. 超时设置
- 消息接收超时：3-10 秒（根据测试复杂度调整）
- 连接超时：5 秒
- 遗嘱消息测试超时：10 秒（需要时间检测异常断开）

### 3. 测试隔离
- 每个测试类通过 `[Collection]` 属性控制并发
- ComprehensiveMqttIntegrationTests 和 MultiProtocolIntegrationTests 使用不同的 Collection，可以并行运行
- 每个测试方法都使用独立的客户端 ID

## 扩展测试

如需添加新的集成测试，建议：

1. **简单功能测试**：添加到 ComprehensiveMqttIntegrationTests.cs
2. **协议版本特性**：添加到 MultiProtocolIntegrationTests.cs
3. **复杂场景测试**：创建新的测试类，使用独立的 Collection

## 常见问题

### Q: 测试超时失败
A: 检查服务端日志，确认消息是否正常发送和接收。可以适当增加超时时间。

### Q: 端口冲突
A: 确保所有测试使用 `Port = 0` 自动分配端口。

### Q: 跨协议通信失败
A: 检查服务端是否正确支持多协议版本，查看编解码器是否正确处理不同版本的消息。
